# Running HUB

> 从活动发布、实名报名、签到管理到回顾互动的一站式校园跑团活动管理平台。

## 项目背景

Running HUB 基于校园跑团实际活动组织场景设计，针对传统活动依赖微信群接龙、报名信息分散、审核与签到效率低、临时退出难管理等问题，提供覆盖**活动发布、报名、审核、签到、退出及活动回顾**的完整活动管理流程。

项目以跑团**管理员与普通成员**为核心用户，采用移动端优先的交互方式，提升校园跑团活动组织与参与效率。

## 用户与角色

| 角色   | 核心需求             | 主要功能                               |
| ---- | ---------------- | ---------------------------------- |
| 普通用户 | 快速获取活动信息并完成报名、签到 | 活动浏览、实名报名、报名状态查看、退出活动、签到、活动回顾、点赞评论 |
| 管理员  | 高效完成活动组织与参与者管理   | 活动发布、活动编辑、报名审核、签到管理、退出管理、活动回顾发布    |

## 核心业务流程

活动发布 → 活动浏览 → 报名 → 审核 → 签到 → 活动回顾

## 功能特性

### 账号体系

* 支持手机号 + 密码登录
* 注册时绑定姓名、性别、学号、学院等用户信息
* 手机号、学号、身份证号进行唯一性校验
* 根据用户身份进入对应功能界面
* 管理员与普通用户采用差异化权限控制
* 支持统一登录及用户身份识别

### 活动管理

* 管理员发布跑步活动
* 支持活动文字介绍及最多 9 张活动图片
* 支持配置活动报名方式及跑团群二维码
* 支持实时编辑活动信息及更换二维码
* 活动列表支持按浏览热度排序
* 活动详情展示活动时间、地点、人数及相关说明

### 报名与审核

* 用户在线提交活动报名
* 管理员对报名申请进行审核
* 用户实时查看报名审核状态
* 活动人数达到上限时限制继续报名
* 通过数据库行锁控制高并发场景下的名额竞争
* 审核通过后开放对应活动群信息
* 被拒绝的报名申请不可重复提交同一活动
* 用户退出活动需填写退出原因
* 管理员可对异常退出进行标记

### 签到管理

* 管理员查看活动参与人员及签到情况
* 活动签到状态实时更新
* 已签到、未签到人员进行区分展示
* 活动结束后可查看参与情况
* 对未签到人员自动生成对应记录

### 活动回顾

* 管理员发布活动总结及活动图片
* 用户查看活动回顾
* 支持点赞与评论互动
* 点赞采用幂等处理，避免重复操作
* 用户公开互动时仅展示昵称

### 隐私设计

* 用户实名信息仅对管理员开放
* 普通用户之间不展示身份证号、手机号等敏感信息
* 公开互动统一使用用户昵称
* 测试及演示数据采用虚拟数据，避免暴露真实个人信息

## 快速开始

### 1. 初始化数据库

创建 MySQL 数据库，并执行：

```bash
mysql -u root -p < sql/init.sql
```

### 2. 启动后端

创建虚拟环境并安装依赖：

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

配置 `.env` 后启动服务：

```bash
uvicorn app.main:app --reload --port 8080
```

后端接口文档：

```text
http://localhost:8080/docs
```

### 3. 启动前端

```bash
cd frontend
npm install
npm run dev
```

前端默认运行在：

```text
http://localhost:5173
```

## 部署

项目支持基于 **Nginx + systemd** 的部署方式：

* Nginx 负责前端静态资源及请求转发
* FastAPI 提供后端 API 服务
* systemd 负责后端服务进程管理
* MySQL 提供业务数据存储
